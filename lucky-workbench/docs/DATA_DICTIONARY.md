# OPC TRADE LAB V1 — DATA DICTIONARY & SCHEMA CONTRACTS

## 1. Provenance Classifications
Every snapshot, order, execution, and report carries a single immutable provenance:

| Provenance Enum | Description |
|---|---|
| `SYNTHETIC` | Generated by deterministic test fixtures (e.g. `demo-v1`). |
| `RECORDED_LIVE` | Historically captured from live public exchange APIs with verifiable timestamps. |
| `LIVE_READONLY` | Real-time live read-only feed streaming from public order books. |

**Anti-Corruption Rule:** Mixed provenance in a single replay run is strictly prohibited and rejected by `ReplayRunner`.

## 2. Order States (`OrderState`)

```text
CREATED -> VALIDATED -> QUEUED -> SUBMITTED_SIM -> [ FILLED | PARTIALLY_FILLED | REJECTED | EXPIRED | CANCELLED ]
```

- `CREATED`: Trade intent generated from signal.
- `VALIDATED`: Passed strategy and risk checks.
- `QUEUED`: Reserved cash in accounting ledger.
- `SUBMITTED_SIM`: Latency delay timer active.
- `FILLED`: Both Leg A and Leg B fully executed for $q$ shares with zero residual.
- `PARTIALLY_FILLED`: One or both legs executed partially; residual logged in inventory.
- `REJECTED`: Blocked by risk manager or invalid parameters prior to reservation.
- `EXPIRED`: No matching future snapshot tick found within latency window.
- `CANCELLED`: Order book crossed, invalidated, or closed during execution window.

## 3. Monetary Quantization Standards

All numbers are handled via Python `decimal.Decimal` and serialized as decimal strings:
- **Price (`quantize_price`)**: 4 decimal places (`0.0001`), `ROUND_HALF_UP`.
- **Shares (`quantize_shares`)**: 2 decimal places (`0.01`), `ROUND_DOWN` (conservative).
- **Cash / NAV / P&L (`quantize_money`)**: 4 decimal places (`0.0001`), `ROUND_HALF_UP`.
- **Float Leakage**: Strictly forbidden. Zero `float()` conversions in the accounting path.
